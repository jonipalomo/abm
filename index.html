Otro dispositivo

Abrir todo esto en otra computadora

El repositorio vive en GitHub (la "nube"). Si estás en una máquina nueva —tuya, del aula, o la de tu compañero— así lo bajás:

1. Verificar que tengas Git y Python instalados

# en una terminal (PowerShell, cmd o bash)
git --version
python --version
¿No tenés Git? Instalalo desde git-scm.com/downloads. Python desde python.org/downloads (marcá "Add to PATH" en el instalador de Windows).

2. Clonar el repositorio

# trae una copia completa del proyecto, con todo su historial
git clone https://github.com/jonipalomo/abm.git
cd abm

3. Abrir las guías

Doble clic en index.html La forma más simple: se abre en el navegador por defecto, sin nada más que instalar
python servir-guias-red.py Sirve las guías en tu red Wi-Fi, para abrirlas también desde el celular

4. (Opcional) Levantar el proyecto Django completo

# instala dependencias, prepara la base y corre el servidor
pip install -r requirements.txt
python manage.py migrate
python manage.py runserver
¿Ya tenías el repo clonado en ese dispositivo? No lo clones de nuevo: entrá a la carpeta y traé lo último con git pull. Cloná solo la primera vez en cada máquina.

Resumen

Paso a paso completo, de cero a trabajando en equipo

Si preferís una sola lista en vez de navegar por secciones, este es el camino completo:

  • 1. Instalar Git y Python en tu máquina Verificalo con git --version y python --version.
  • 2. Clonar el repositorio desde GitHub git clone https://github.com/jonipalomo/abm.git y entrar con cd abm.
  • 3. Leer la guía de conceptos Entender MVT, ABM/CRUD y cómo está modelado Alumno antes de tocar código.
  • 4. Leer la guía de Git y GitHub Comandos del día a día y cómo backend/frontend avanzan en paralelo con ramas y PRs.
  • 5. Hacer el ejercicio de conflicto de merge Provocar uno a propósito y resolverlo, para perderle el miedo antes de que pase de verdad.
  • 6. Levantar el proyecto y probar el ABM pip install -r requirements.txt, python manage.py migrate, python manage.py runserver.
  • 7. Elegir un rol y trabajar en una rama propia Backend o frontend, según lo que viste en la guía de conceptos. Rama, commits, push, Pull Request.
